# CL-013 计划与回滚：planId 三分支 + backupId 逆序恢复（v0.10.0）

> 日期：2026-11-27 · 参考：yasewang1337-svg/winutil-cn（`plans.mjs` 规范化指纹 + 一次性 + TTL；
> `worker-core.ps1` 的 GUID-only 恢复与逆序还原）、microsoft/winget-cli（协议级同意、不代用户接受）
> 上游调研：`deep-research/win-mcp-skill-plugin/win-mcp-skill-16-proj-review.md` §2.2 与「横向综合」第 1 条

## 1. 补的是什么

之前写操作只有一条路：**申请审批 → 直接执行**。缺两样东西：

1. **执行前能不能看清楚会发生什么**（预览 / 计划 / blocker）
2. **执行后能不能一键退回去**（备份 / 回滚）

这一轮把 `preview → planId → confirm → 执行 → backupId` 这条链补齐。

## 2. planId 三分支

`apps.winget.plan`（L1，零副作用）→ `apps.winget.apply`（L2，需审批）。

| 分支 | 触发条件 | apply 行为 |
|---|---|---|
| `blocked` | winget 不可用 / ID 含空格（像显示名）/ ids 为空 | 抛 `PLAN_BLOCKED`，**一个都不执行** |
| `no-changes` | 已装又要装 / 未装又要卸 | 返回 `status=no-changes`、`executed=0`，**不算失败** |
| `ready` | 存在真实变更 | 逐项执行，逐项记录，失败不中断后续 |

关键约束（逐条对应上游教训）：

- **参数指纹**：`canonicalJson({operation, ids})` 必须与预览时完全一致，否则 `PLAN_MISMATCH`。
  key 顺序不同但语义相同是允许的（规范化后一致）。
- **一次性**：消费即删除；复用返回 `PLAN_NOT_FOUND`。
- **不消耗即失败**：`PLAN_MISMATCH` 时**不删除**计划，避免"试错把计划烧掉"后要重新预览。
- **TTL 5 分钟 + 容量 100**（LRU 淘汰最旧）。
- **planId 不等于用户同意**：`confirm: z.literal(true)` 是 schema 强制，且说明里点名"必须已展示给用户"。
  server 只证明"这次调用与那次预览一致"。
- **失败不假装可回滚**：返回 `rollback` 字段说明"第三方安装器不支持自动回滚"，
  部分失败时 `effectState=unknown`，并明确"不要重试同一 planId"。

### 已装检测为什么用 `winget list` 而不是注册表

`Get-InstalledApps` 只有 `DisplayName`，没有 winget 包 ID，用它匹配 ID 会误判。
新增 `Get-WingetInstalledState`：跑一次 `winget list`，用 Id 列做子串匹配。
这是**启发式**（一次调用比 N 次 `list --id` 快得多），已在文档与 warnings 里标注。

## 3. backupId 回滚

### 3.1 备份

`system.registry.write` 现在统一走 `New-SettingsBackup`：

```
%LOCALAPPDATA%\win-mcp\backups\<GUID>.json
{ schema, backupId, operation, machine, user, createdAt, entries: [...] }
```

entries 里 registry 项记录 `exists / value / valueType / keyExisted`，
service 项记录 `exists / startType / status`。写入前捕获，写失败也不影响已有备份。

> 与上游差异：winutil 用 `%ProgramData%` + ACL 加固（Administrators/SYSTEM only）。
> 我们在**非提权**下运行，ProgramData 建目录并加固 ACL 需要管理员，所以用 `%LOCALAPPDATA%`。
> 代价：备份文件对同用户可读可改 —— 已写进 `CL-013` 边界，别当成防篡改存储。

### 3.2 恢复（四条硬规则）

1. **只接受 GUID**：正则校验，路径注入直接 `INVALID_PARAMS`（实测 `C:\Windows\win.ini` 被拒）。
2. **逆序恢复**：同一项被多次修改时，先撤销最后一次改动才回到正确状态。
3. **精确还原"不存在"**：原本没这个值时 `Remove-ItemProperty`，而不是写默认值。
4. **跨机拒绝 + 空键保留**：`machine` 不匹配直接拒；键本身是新建的保留空键，
   因为删除可能抹掉其他程序刚写入的值。

## 4. 实测证据（真机）

```
PL-01 未安装 + uninstall         → no-changes
PL-02 no-changes 执行            → executed=0
PL-03 planId 复用                → PLAN_NOT_FOUND
PL-04 显示名（含空格）            → blocked
PL-05 blocked 执行               → PLAN_BLOCKED
PL-06 未安装 + install           → ready
PL-07 参数不一致                  → PLAN_MISMATCH
BK-01 首次写入（值不存在）         → backupId 生成, previousExists=false
BK-02 覆盖写入                    → previousExists=true
BK-03 回滚第二份                  → 值恢复为 v1
BK-04 回滚第一份                  → 值被删除（exists=false）
BK-05 路径注入                    → INVALID_PARAMS
BK-06 不存在的 GUID               → BACKUP_NOT_FOUND
BK-07 备份列表                    → count>=2
```

## 6. 顺手修的一个一致性问题

`system` 域所有 handler 之前没走 `guard()`，桥的领域错误码（`BACKUP_NOT_FOUND`、`INVALID_PARAMS`）
到能力面就退化成 `INTERNAL`。现在统一 `guard()` 包裹，错误码可区分。
这个缺陷是被 BK-05/BK-06 两条冒烟逼出来的——如果只测"成功路径"，它会一直藏着。

## 7. 边界

- **第三方安装器不可回滚**（明确写在返回值里，不承诺做不到的事）。
- **备份不含文件删除**：只覆盖注册表值与服务启动类型，不管被安装/删除的文件。
- **服务备份只到 StartMode + Status**：不含失败恢复动作、依赖关系等更深配置。
- **`Get-WingetInstalledState` 是子串匹配**：极端情况下同名子串会误判（已在 warnings 披露）。
- **备份不加密不签名**：同用户可改，仅用于"操作失误回退"，不是合规审计存储。
