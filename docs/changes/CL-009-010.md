# CL-009 / CL-010 — Skill bundle 与客户端接入包

> 版本 v0.7.0 · 2026-11-26 · 合并版 DDD 记录

## 1. 范围

### CL-009：6 个 Skill bundle

`skills/<server>/SKILL.md`，每个含：

- YAML frontmatter：`name` / `description` / `tags` / `triggers` / `requirements` / `risk`
- 能力速查表（工具 → 风险 → 说明）
- 3 个典型场景 SOP（步骤序列，含"先 analyze 再 invoke"这类强制顺序）
- "不要做"清单（把硬禁与应用层禁忌写进 skill，而不是只靠服务端拒绝）

| Skill | 核心 SOP |
|---|---|
| `win-system` | 服务排查 / 变慢排查 / 改注册表（读→写→备份） |
| `win-shell` | 执行前强制 `shell.cmd.analyze`；硬禁改写建议 |
| `win-apps` | 安装四步（info→search→install→核验）/ 卸载三步 |
| `win-resource` | "磁盘满了"四步（space→analyze→execute→复查） |
| `win-desktop` | 截屏展示 / 关窗口前确认标题 / 剪贴板提示 |
| `win-browser` | 加书签五步（含"必须先关浏览器"）/ 删除前确认同名 |

**设计取舍**：Skill 只写"怎么用"与"别做什么"，不重复工具 schema。工具描述在 MCP 侧是权威，Skill 是场景编排层。

### CL-010：接入包

- `examples/clients/mcp.json`：6 server 的 stdio 完整配置
- `examples/clients/README.md`：各客户端放置位置、按需启停、HTTP 模式、常见问题、审批交互要点

## 2. 关键内容

### 2.1 建议的挂载策略

日常只挂 `win-system` + `win-resource`（只读为主、审批少）；需要跑命令时再临时加 `win-shell`。理由：命令通道一旦常驻，Agent 倾向用它绕开专用能力（例如用 `Stop-Service` 而不是 `system.service.control`），削弱了分级与审批的意义。

### 2.2 HTTP 注意

必须用 `localhost` 而非 `127.0.0.1`：本机若启用 NekoBox TUN 模式，裸 IPv4 回环可能被拦截；`localhost` 解析到 `::1` 更稳。

## 4. 遗留

| 项 | 说明 |
|---|---|
| Skill 未做自动发现 | 需要客户端支持 `skills/` 目录；当前靠用户手动放置或客户端扫描 |
