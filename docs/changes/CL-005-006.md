## 2. 方案

### 2.1 `apps.ps1`

- `Get-InstalledApps`：读三条 Uninstall 路径，取 DisplayName/Version/Publisher/InstallDate/EstimatedSize/UninstallString，统计 `totalMatched` 后再截断
- `Get-WingetInfo` / `Invoke-WingetAction`：包装 `winget`，返回 `exitCode + lines(前80) + text(截断)`；search/install/uninstall/upgrade 分别组装参数与 `--accept-*` 协议
- `Start-Application`：**先按 PATH 解析命令名**，再退回文件路径。这样调用方不需要传 `C:\Program Files\...` 绝对路径——那会被路径黑名单拒绝

### 2.2 `resource.ps1`

- `Get-ResourceMetrics`：`Win32_OperatingSystem` + `Win32_PerfFormattedData_PerfOS_Processor(_Total)` + `Win32_VideoController`
- `Get-VolumeSpace`：`Get-Volume`，过滤无盘符卷
- `Get-CleanupAnalysis`：递归统计用户/系统 TEMP 的大小与文件数（只读）
- `Clear-UserTempFiles`：**只处理 `$env:TEMP` 根目录下的文件**（非递归删目录、不碰系统目录），支持"仅删早于 N 分钟"与单次上限，返回 `deleted/failed/freedMB`

## 3. 能力 ID 修正（实现中踩到）

- 域是 `apps` 而非 `app`（`CAPABILITY_DOMAINS` 白名单），`app.list.installed` 注册即抛 `INVALID_CAPABILITY_ID`
- `apps.launch` 只有两段 → 改 `apps.app.launch`

## 5. 与架构设计的偏差（诚实记录）

| 设计 | 本轮实现 | 原因 |
|---|---|---|
| 软件装卸走 `planId → confirmPlan → backupId` 三分支 | 只实现两阶段审批（`__approvalId`） | planId 分支需要 plan 存储与 canonical 快照，工作量独立；两阶段审批已满足"预览+确认+防掉包" |
| 资源调优 `snapshot/apply/rollback` | 未实现 | 调优脚本集与回滚基线需单独设计，且激进项风险高；本轮只做"检测 + 清理" |
| winget 结果结构化 | 返回 `exitCode + lines` | winget 无稳定的 JSON 输出契约；文本行足够 Agent 判断 |

## 6. 遗留

| 项 | 说明 |
|---|---|
| winget 输出为文本 | 依赖本地化文案，Agent 应以 exitCode 为准 |
| 清理不含回收站/WinSxS | 需管理员与额外安全设计 |
| `apps.list.installed` 不含 AppX | AppX 需 `Get-AppxPackage`，语义与卸载方式不同，留后续 |
| 无软件更新检查 | `winget upgrade` 已可用但未封装为独立能力 |
