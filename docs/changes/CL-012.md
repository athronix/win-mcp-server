## 1. 为什么这一轮必须做 CDP

CL-011 实测证实：**Electron/Chromium 窗口默认不向 UIA 暴露语义树**，`desktop.ui.snapshot` 只能看到
一个空的 `Chrome Legacy Window`（见 `CL-011.md` §4）。而同一批应用的 DOM 一定是完整的，
所以页面级自动化必须走 CDP，而不是继续在 UIA 上打补丁。

## 3. 三个关键设计

### 3.1 ref 与"动作前重取事实"

- ref 格式 `@b<snapshotId>:e<index>`，页内实现是 `window.__wmcRefs[index]`。
- **页面导航会清空该数组** → 旧 ref 直接 `STALE_REF`，这正是想要的行为（不需要额外的 documentId 机制）。
- 跨快照使用（快照序号已推进）在 Node 侧就被拒，不会下发到页面。
- 动作前用 `tag + 文本指纹` 复核元素仍是同一个；`isConnected === false` 判 `STALE_REF`。
- `expect` 支持 `exists / text / value / checked / attribute`，≤16 条，**在动作之前**在页面里求值，
  任一条不满足就 `GUARD_ASSERTION_FAILED`，绝不"照旧 ref 硬点"（BrowserSkill 的核心教训）。

### 3.2 启动与连接

- 端口传 `0`，让系统分配，再从 `<profile>\DevToolsActivePort` 读回真实端口 —— 避免固定 9222 冲突。
- **启动前先删残留的 `DevToolsActivePort`**：上一轮实例退出后文件还在，直接读会拿到死端口（实测踩过）。
- 只等文件出现不够：文件先落盘、端点后监听。必须轮询到 `/json/version` 真的可服务（最多 20s）。
- 回环主机名两个都试：DevTools 只绑 `127.0.0.1`，而本机 NekoBox TUN 会拦裸 IPv4 回环；
  `swapLoopbackHost` + `connectEndpoint` 依次尝试，避免环境差异导致挂死。
- 独立 profile（`%LOCALAPPDATA%\win-mcp\browser-profile`）**不碰用户日常登录态**，代价是没有登录态。

### 3.3 target 字段不一致（踩坑）

`/json/list` 返回 `id`，`Target.getTargets` 返回 `targetId`。混用会导致
`Target.attachToTarget: Invalid parameters`（因为我们把 `undefined` 当 targetId 发了出去）。
统一收敛到 `targetIdOf(target)`。

## 4. 实测证据（headless Edge 158）

```
CD-02 独立 profile 启动并读回真实端口    → port=53497, Edg/158.0.4370.33
CD-05 DOM 语义快照                     → nodes=5（body/heading/button/textbox/div）
CD-07 setValue 走原生 setter 并回读      → via=value-setter, value="hello cdp"
CD-08 click + 动作前断言                → via=element.click, #out: idle → clicked
CD-09 旧快照 ref                       → STALE_REF
CD-10 断言不满足                       → GUARD_ASSERTION_FAILED
CD-11 页面截图                         → 6862 B PNG
```

端到端耗时：启动 ~1.0s，快照 ~5ms，动作 ~10ms。

## 6. 边界（明确没做）

- **无真实登录态**：独立 profile 没有 cookie/扩展。要复用日常 profile 需要先彻底退出浏览器，
  再用 `--remote-debugging-port` 启动；本版本没提供该模式（避免误判"抢"用户浏览器）。
- **无网络域能力**：不抓包、不做性能 trace、不拦请求（chrome-devtools-mcp 那套）。
- **无 iframe 递归**：快照只走主 frame，跨域 iframe 需要切换 executionContext。
- **无文件上传/下载**：`DOM.setFileInputFiles` 与下载目录接管未做。
- **无遮挡检测**：agent-browser 的"点击点被遮挡即失败"没做，`element.click()` 本身会绕过遮挡。
- **`browser.cdp.eval` 是逃生口**：它让上面这些"没做"都能用脚本绕过——所以定级 L3 强制人工审批。
