# CL-004 — win-shell（命令通道）

> 版本 v0.4.0 · 2026-11-26 · 合并版 DDD 记录

## 1. 范围

`win-shell` 是最高危 server：PowerShell 与 Git-Bash 两条命令通道。

| 能力 | 风险 | 说明 |
|---|---|---|
| `shell.env.info` | L0 | PS 版本、是否提权、Git-Bash 路径与版本 |
| `shell.cmd.analyze` | L0（`analysisOnly`） | 官方 AST 预检，返回分级/语法错误/命令/路径，**不执行** |
| `shell.cmd.invoke` | 动态 L0–L3 | 真 AST 判级 → 审批 → 独立 runspace 执行 |
| `shell.bash.invoke` | 动态 L0–L3 | bash 词表分级 → 审批 → `bash -lc` 执行 |

**不做**：人类可见控制台、密码人输、UAC 提权（需独立窗口与交互，留 CL-004b）。`runAsAdmin` 本轮只做"非提权会话直接拒绝"。

## 2. 方案

### 2.1 bash 分级（`src/shell/bash-classify.ts`，纯函数）

| 档 | 词表（节选） |
|---|---|
| L0 | ls/pwd/cat/head/tail/grep/find/which/whoami/id/date/df/ps/env/echo/wc/sort/uniq/cut/stat/tree/diff… |
| L1 | mkdir/touch/cp/mv/ln/tee/tar/zip |
| L2 | rm/rmdir/chmod/chown/dd/mount/kill/sed/awk/npm/pip/python/node/git/docker/ssh… |
| L3 | sudo/su/passwd/useradd/chroot/iptables/shutdown/reboot/mkfs/fdisk/systemctl/reg/bcdedit… |

硬禁（blocked，无审批通道）：`rm -rf /`（或 `~`/`$HOME`）、fork bomb、`curl|sh`/`wget|sh`、`eval`、`dd of=/dev/`、`mkfs.`、`>/dev/sd*`、`chmod 777 /`。
额外升级：写 `/etc` `/usr` `/bin` `/var` 等 → L3；`git push/reset --hard/clean -f` → L2；`sed -i` → L2。

### 2.2 组合判级器

```
createShellClassifier(bridge)
  ├─ capabilityId === 'shell.bash.invoke' → analyzeBashCommand()
  ├─ params.runAsAdmin && !bridge.info.elevated → blocked ADMIN_REQUIRED
  └─ 其它 → createBridgeClassifier(bridge)（真 AST）
```

### 2.3 执行

- `shell.cmd.invoke` → 桥 `op=invoke`（独立 runspace + 超时 Stop）
- `shell.bash.invoke` → 桥 `op=module` → `shell.ps1: Invoke-BashCommand`（`[powershell]::AddScript('param($bash,$cmd) & $bash -lc $cmd')` + `AddArgument` 避免拼接注入 + `WaitOne` 超时 Kill）

`shell.ps1` 的 `Get-ShellInfo` 会用"标准路径候选 + `Get-Command bash`"探测 Git-Bash。

## 3. 实现中发现并修复的策略缺口

### 3.1 预检能力被命令黑名单误拦

`shell.cmd.analyze` 的参数 `command: "iex ..."` 会命中全局命令黑名单（`\biex\b`）→ `POLICY_DENIED`。
**但预检的用途正是分析危险命令**，被拦等于预检失效。

修复：新增能力标记 `analysisOnly`。`PolicyEngine.evaluate` 在校验能力 ID 后直接放行（`allow:analysis-only`），跳过路径/命令检查。
代价与约束：使用该标记的能力 **handler 必须无副作用**——目前只有 `shell.cmd.analyze` 使用，代码注释与文档双重标注。

### 3.2 `$env:TEMP` 路径被白名单误拒

`Remove-Item "$env:TEMP\x"` 的 AST 证据是字面 `$env:TEMP\x`，路径白名单是 `C:\Users\**` 等真实路径 → `pathAllowlist:miss`，导致一条本应走审批的命令被直接拒绝。

修复：`policy/glob.ts` 新增 `expandEnvVars()`，`PolicyEngine` 构造可注入 `env`（默认 `process.env`），路径归一化前先展开 `$env:NAME`。现在 `$env:TEMP\x` → `C:\Users\<user>\AppData\Local\Temp\x` → 命中 `C:\Users\**` → L2 审批。

### 3.3 能力 ID 必须三段式

`shell.info` / `shell.analyze` / `shell.invoke` / `shell.bash` 只有两段，注册时抛 `INVALID_CAPABILITY_ID`。
统一改为 `shell.env.info` / `shell.cmd.analyze` / `shell.cmd.invoke` / `shell.bash.invoke`。

## 5. 遗留

| 项 | 说明 |
|---|---|
| 无人类可见控制台 | 密码仍可能经参数进入上下文；CL-004b 用独立 `conhost`/`wt` 进程 + 人读密码解决 |
| bash 不支持 runAsAdmin | Git-Bash 提权语义不明确，暂不提供 |
| bash 词表非穷尽 | 未知命令保守 L2；可随使用逐步补全 |
| 超时的写命令效果未知 | 返回 `TIMEOUT`，上层应视为 `effect_state=unknown` 并让用户核销 |
