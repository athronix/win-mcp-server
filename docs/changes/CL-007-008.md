# CL-007 / CL-008 — win-desktop 与 win-browser

> 版本 v0.6.0 · 2026-11-26 · 合并版 DDD 记录

| server | 能力 | 风险 |
|---|---|---|
| `desktop.screen.capture` | 全屏截图（多显示器虚拟屏）→ PNG 文件 | L0 |
| `desktop.window.list` | 可见顶层窗口枚举（句柄/标题/进程） | L0 |
| `desktop.window.control` | minimize/maximize/restore/activate/close | L2 |

## 2. 关键设计

### 2.1 desktop.ps1

- P/Invoke（`WinMcpDesktop` 类，`Add-Type` 前做类型存在性检查）：`EnumWindows`/`GetWindowText`/`ShowWindow`/`SetForegroundWindow`/`PostMessage`/`GetSystemMetrics`
- 截图用 `System.Drawing` + `GetSystemMetrics(76..79)` 覆盖多显示器虚拟屏；`maxWidth` 用 `HighQualityBicubic` 等比缩放；**返回 PNG 文件路径而非 base64**（避免撑爆上下文）
- 窗口枚举跳过不可见与空标题窗口；回调里用 `$processId` 而不是 `$pid`（后者是只读自动变量）

### 2.2 browser.ps1（不用 CDP 的书签方案）

书签直接读写 `User Data\<Profile>\Bookmarks` JSON：

- `Get-BookmarkNodes` 递归 `bookmark_bar` / `other` / `synced`，扁平化并记录所在文件夹
- 写操作前 `Backup-BookmarksFile` 备份到 `%LOCALAPPDATA%\win-mcp\backups\bookmarks-*.json`
- 新 id 用现有最大 id + 1；`date_added` 用 Chrome 时间戳（1601 纪元微秒）
- 删除用递归 `Remove-BookmarksByMatch`（按 id 或 url）
- **必须提示用户先关浏览器**：浏览器退出时会用内存状态覆盖该文件，写入会被丢

> 这个方案覆盖了"添加/打开/删除书签"这一 CDP 系工具（agent-browser / chrome-devtools-mcp / playwright-mcp）都不提供的缺口，代价是不支持页面交互。

## 3. 实现中修复的策略缺陷

**URL 被当成文件路径**：`browser.bookmark.add` 的 `url=https://example.com/` 含 `/`，`looksLikePath` 返回 true → 走路径白名单 → `C:\Users\**` 不匹配 → `POLICY_DENIED`。

修复：`policy/glob.ts` 的 `looksLikePath` 先排除 URI scheme（`^[a-z][a-z0-9+.-]*://`）。加回归用例 P-24。

## 5. 遗留

| 项 | 说明 |
|---|---|
| 无 UIA / 键鼠注入 | 无法点击界面元素；需 `uiautomation` 或 FlaUI 封装，风险与工作量都高 |
| 无桌面门控 | 未实现 CursorTouch 式 relaxed/balanced/strict + 倒计时同意 |
| 书签写入依赖浏览器关闭 | 未做检测（可检查进程存在并拒绝）；当前只在 instructions 与返回 note 里提示 |
| 仅支持 Chrome/Edge | Firefox 的 `places.sqlite` 结构不同，未实现 |
| 截图为文件路径 | Agent 需要再读文件；MCP 客户端若不支持文件读取则看不到图 |
