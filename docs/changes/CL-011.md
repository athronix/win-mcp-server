## 1. 这一轮补的是什么

CL-007 的 win-desktop 只能截屏、关窗口、读写剪贴板——**不能点按钮**。CL-011 把"看"和"动"补齐：

| 能力 | ID | 风险 | 说明 |
|---|---|---|---|
| UIA 语义树快照 | `desktop.ui.snapshot` | L0 | 扁平前序节点列表，带 `@s<N>:e<M>` ref、role、states、actions、bounds |
| 按 ref 操作 | `desktop.ui.act` | L2 | click/doubleClick/rightClick/setValue/focus/toggle/expand/collapse/select/scrollIntoView/getText |
| 键鼠注入 | `desktop.input.send` | L2 | press（组合键）/type（Unicode 直送）/click/move/scroll/drag |
| 门控状态 | `desktop.control.state` | L0 | 策略、租约剩余、空闲毫秒、前台窗口、光标 |
| 门控策略 | `desktop.control.policy` | L3 | relaxed / balanced / strict |

## 2. ref 语义（照 agent-desktop 收窄到可落地的最小集）

- `ref = @s<snapshotId>:e<index>`，**裸 `@e8` 被拒**（`INVALID_PARAMS`）——没有快照 id 就无从判断陈旧。
- 动作前**重新识别元素**，三级降级：
  1. `live-object`：快照时捕获的 UIA 元素仍存活且 `GetRuntimeId()` 未变 → 直接用；
  2. `runtime-id`：元素被重建，在同窗口内按 runtimeId 重找（唯一命中才用）；
  3. `identity`：按 `role|automationId|name` 重找，**必须唯一**，多个命中抛 `AMBIGUOUS_TARGET`；
  4. 都不中 → `STALE_REF`，提示重新快照。
- 快照保留最近 8 份；用过期快照 id 会得到 `STALE_REF` 而不是静默解析到新快照。

> 与 agent-desktop 的差异：它做"捕获时唯一性证明"（`ref_capture_proof`），我们用 runtimeId 做等价约束。
> runtimeId 本身就是窗口内唯一标识，成本低得多；代价是 UI 重建后必须重新快照（语义正确，只是不够"抗刷新"）。

## 3. 桌面门控（照 CursorTouch 的 control_policy 单表）

`packages/core/src/desktop/control-policy.ts` 是唯一分类处：

| 分类 | 含义 | 能力 |
|---|---|---|
| `direct` | 直接注入鼠标键盘 | `desktop.ui.act`、`desktop.input.send`（press/type/click/scroll/drag）、`desktop.window.control`（activate/minimize/maximize/restore） |
| `possible` | 可能打断用户 | `desktop.clipboard.set`、`desktop.window.control`（close） |
| `other` | 后台/只读 | 快照、窗口列表、截屏、剪贴板读、门控状态 |

判定：

- `relaxed`：只拦 `direct`
- `balanced`（默认）：拦 `direct` + `possible`
- `strict`：除 `desktop.control.state` 外全拦
- **未登记能力按 `direct`**（fail closed）——新增能力忘登记会直接要求授权，而不是悄悄放行
- `desktop.control.state` 在**任何**策略下免检，否则"查谁在控制桌面"本身要授权，形成死锁

`packages/servers/tests/desktop-browser.test.ts` 有覆盖测试：`unclassifiedCapabilities(desktopCapabilities().map(c => c.id))` 必须为空数组。

### 3.1 倒计时同意（独立进程 + 退出码协议）

`packages/core/ps/consent-dialog.ps1` 由 `createSpawnConsentRunner` 以独立进程启动：

| 退出码 | 含义 |
|---|---|
| 10 | 立即允许 |
| 11 | 拒绝（按钮或关窗） |
| 12 | 倒计时无应答 → 自动允许（保证无人值守） |
| 13 | 无交互会话 / WinForms 不可用 |

三条硬约束：

1. `stdio: ['ignore','ignore','ignore']`——绝不能碰 server 的协议管道；
2. 答案只走退出码，stdout 不做通道；
3. **对话框挂起/崩溃 → `unavailable` → `CONTROL_DENIED`**。

第 3 条与上游**故意不同**：CursorTouch 把挂起也当超时允许，那等于"弄挂对话框即可获得控制权"。我们 fail closed。

### 3.2 租约与夺回

- 一次同意建立一个租约，默认空闲 5 分钟失效（`leaseTtlMs`），失效后重新弹窗。
- 夺回判定：`idleMs < 600ms` **且** 距我方最后一次输入 > 900ms → 判为用户夺回 → 撤销租约、抛 `USER_CONTROL`。
- 明确记录：**门控是协调不是安全边界**。用户随时能夺回，我们不保证独占；`GetLastInputInfo` 是 best-effort 证据。

## 4. Chromium/Electron：命中的坑与结论

实测 WorkBuddy（Electron）窗口，UIA 顶层只有 2 个节点：

```
@s1:e0 window "WorkBuddy"
@s1:e1 group  "Chrome Legacy Window"     # 子树为空
```

处理过程与结论：

1. 枚举子窗口能找到 `Chrome_RenderWidgetHostHWND`（1 个），已实现 `Get-RenderHostHandles`；
2. `AccessibleObjectFromWindow(OBJID_CLIENT, IID_IAccessible)` 在本机返回非 0（拿不到 MSAA 对象），
   持有对象防释放的写法也保留着（对部分 Chromium 版本有效）；
3. 以渲染宿主 HWND 为快照根 `FromHandle(hwnd).FindAll(Descendants)` 仍为 0 个后代；
4. 结论：**Electron 应用默认不暴露 UIA 树**，需要应用侧 `--force-renderer-accessibility`
   或 `app.setAccessibilitySupportEnabled(true)`。

因此 `Get-UiTree` 在"有渲染宿主但节点 ≤2"时返回 `warnings`，明确告知改走 `win-browser` 的 CDP 通道（CL-012）。
原生 Win32/WPF/UWP（资源管理器、设置、记事本）实测正常：**204 节点**，含 `click/expand/select/setValue` 动作。

最小化窗口也会有同样症状（子树几乎为空），所以 `IsIconic` 命中时也返回 `warnings` 提示先 restore。

## 5. 实现里揪出的 4 个真缺陷

1. **`ArrayList.Add` 返回 int，不是 void** —— 递归里每个层级都往函数返回值里漏一个 int，
   导致上层拿到 `Object[]` 再去 `List[int].Add()` 报"找不到 Add 的参数计数为 1 的重载"。
   全部加 `[void]`，并把"先建树后前序扁平化"重构掉（原来子节点先入列表，扁平表前序错乱）。
2. **`Rect.Empty` 的 Width/Height 是 `-Infinity`** —— `[int]` 强转直接抛异常，一条快照命令整个 500。
   改为先取 `[double]` 判 `IsNaN/IsInfinity`。
3. **`$matches` 撞正则自动变量** —— 重命名为 `$hits`（与 CL-002 的 `$errors` 撞 `$Error` 同类问题）。
4. **门控先于审批会弹两次窗** —— 门控放在 handler 内，因此只有审批通过后才征求控制权；
   一次 L2 调用最多一次"客户端审批 + 一次"桌面同意，顺序符合直觉。

## 7. 边界（未做，别当成有）

- **无 UIA 事件订阅**：不做 `WaitFor`（等元素出现/消失），只能轮询快照。
- **无批量动作**：FlaUI-MCP 的 `windows_batch` 没做，多步要多次调用（每次都要过审批）。
- **无持久视觉指示器**：CursorTouch 的屏幕边缘琥珀色 + 光标标记没做，用户只能靠同意对话框感知。
- **无按键/按钮持有台账**：不暴露 `key-down`/`key-up`，因此不需要恢复残留按键（这是有意的收窄）。
- **坐标未做多屏换算**：用的是物理像素 + 虚拟屏幕原点，跨屏拖动需要调用方自己算。
- **Electron 仍需外部条件**（见第 4 节）。
